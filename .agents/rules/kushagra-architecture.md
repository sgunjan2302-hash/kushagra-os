# Kushagra OS Architecture & Release Invariants (`v0.2.1+`)

1. **सत्य और रनटाइम सत्यापन (Truthfulness & Runtime Verification):** बिना QEMU/KVM या असल हार्डवेयर पर बूट करके देखे किसी भी बदलाव को "काम कर रहा है" न कहें; अनटेस्टेड चीज़ों को `[UNVERIFIED - NEEDS VM TEST]` टैग करें।
2. **CI रिलीज़ क्रम (Strict Release Ordering):** पहले हमेशा `main` ब्रांच कमिट व पुश करें ताकि कंटेनर और सटीक `image_digest` वाला ISO बन जाए; दोनों के `[PASS]` होने के बाद ही `vX.Y.Z` टैग पुश करें।
3. **Immutable `bootc` व `/var` अनुशासन:** कंटेनर बिल्ड में `/var` के अंदर रनटाइम स्टेट फ़ाइलें न बनाएं (केवल `tmpfiles.d` व `/etc` फ़्लैग्स का सही उपयोग करें); ध्यान रहे `tmpfiles.d/kushagra-oobe.conf` रीबूट पर `kushagra-oobe-pending` दोबारा न बनाए।
4. **डुअल-बूट पार्टिशन सुरक्षा (Dual-Boot Safety):** हमेशा `clearpart --none` रखें, बूट हुई USB, Windows `NTFS`/`BitLocker`, Recovery व मौजूदा `EFI` (`--noformat`) लॉक रखें, और `< 35 MiB` ESP पर चेतावनी दें।
5. **Plasma 6.6+ इनपुट फ़िक्स:** `Plasma Keyboard` को डिफ़ॉल्ट बंद रखकर वर्चुअल कीबोर्ड को `Fcitx5` / `iBus Wayland` पर लॉक रखें (Electron, Dolphin rename व Firefox बग्स से बचाव हेतु)।
6. **KWin शेडर नियम:** कोई भी KWin इफ़ेक्ट COPR से लेयर करने के बजाय BlueBuild में बेस KWin हेडर्स पर कंपाइल करें, `Translucency` बंद रखें, और `low-ram-mode` में ऑटो-ऑफ़ रखें।
7. **प्राइवेसी-प्रथम `K-AI` व Polkit:** कभी बैकग्राउंड स्क्रीन रिकॉर्डिंग न जोड़ें; हर प्रिविलिज्ड एक्शन के लिए स्पष्ट Polkit अनुमति व ऑडिट लॉग रखें।
8. **हार्डवेयर टियर अनुशासन:** लोकल LLM के लिए Vulkan `llama.cpp` प्राथमिकता रखें; कम रैम वाले सिस्टम पर `clamd` ऑटो-स्टार्ट न करें।
9. **सुरक्षा बिना लॉकआउट:** Quad9 के साथ `DNSOverTLS=opportunistic` रखें, और HID वाइटलिस्ट बनाए बिना `usbguard.service` ऑटो-एनेबल न करें।
10. **निषिद्ध सूची (Prohibited Items):** अल्फ़ा `Darling` (`.dmg`), प्रॉपराइटरी ब्लॉब्स, या अस्थायी स्क्रैच फ़ाइलें Git कमिट में न डालें।
11. **समानांतर मल्टी-एजेंट निष्पादन (Parallel Multi-Agent Execution):** एक से अधिक मॉड्यूल या स्वतंत्र फ़ाइलों पर काम हमेशा समानांतर सब-एजेंट्स (`disjoint file ownership` के साथ) को बाँटकर तेज़ी से करें, और अंत में साझा फ़ाइलों का एकीकरण व स्वतंत्र Auditor जांच (`build-verify-os`) अवश्य कराएं।
12. **पूर्व-शोधित स्पेसिफिकेशन निष्पादन (Pre-Researched Spec Execution):** जब यूज़र पहले से शोधित आर्किटेक्चर ब्लूप्रिंट या वर्ज़न स्पेक दे, तो दोबारा व्यापक बाहरी वेब रिसर्च न करें। केवल स्थानीय रिपॉज़िटरी पाथ, लाइव फ़ेडोरा 44 पैकेज/हेडर्स व रनटाइम VM व्यवहार की पुष्टि करके सीधे समानांतर वर्कर्स से निर्माण करें।
13. **8 GB RAM Official 2026 Baseline:** Kushagra OS officially targets **>= 8 GB RAM** (64-bit x86_64, >= 40 GB SSD) as the Standard Tier and **>= 16 GB RAM** as the Pro/Creator/DX Tier. Preserve lean engineering (`zstd` ZRAM, `earlyoom`, `0 MB` idle `k-ai-engine.socket`, and `llvmpipe` software-GPU guards in `kushagra-glass-guard`), but do NOT spend effort on degraded 4 GB legacy feature cuts or 4 GB-only workarounds. Show a non-blocking legacy advisory if RAM `< 8 GB`.
14. **Max-Parallel Fan-Out & Minimal-Chatter Execution (Speed Without Breaking Safety):**
    - **Maximum Parallel Subagents:** Never run independent work sequentially. Whenever a task has 2+ independent units (coding subsystems, reading/auditing multiple CI logs, writing E2E test scripts, static checks, or pre-commit audits), immediately spawn parallel subagents with strict disjoint file ownership (up to 5–6 workers when work splits cleanly). Only the coordinator touches shared integration files.
    - **Zero Idle Wait During CI/QEMU:** While `build.yml`, `iso.yml`, or QEMU runs in the background, use parallel agents to write the next stage's verification scripts, inspect prior logs, or prepare diff artifacts instead of sitting idle.
    - **Batch Shell & Tool Calls:** Combine independent read-only checks, file reads, syntax checks (`audit_repo.py` + `check_bash.sh` + `git status`), and git diagnostics into single batched calls—avoid 1-command-per-turn loops.
    - **Minimal Chatter (Signal-Only Reporting):** Do NOT send repetitive mid-run progress essays or narrate every tool call. Communicate ONLY at: (a) a concrete `[FAIL]`/`[WARN]` blocker (exact file + error line), or (b) final gate completion with a compact bullet/table status (`PASS`/`FAIL`/`UNVERIFIED`) and diff path.
    - **Safety Gates Stay Non-Negotiable:** Speed never bypasses disjoint file ownership, `audit_repo.py`/`check_bash.sh`, Independent Pre-Commit Auditor, or stop-before-push approval.
